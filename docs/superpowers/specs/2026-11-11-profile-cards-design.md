# Profile cards: design

Date: 2026-11-11
Repo: `Wasif0410/Wasif0410` (GitHub profile README), branch `profile-cards`

## Goal

Replace the current emoji-table README with a stack of animated SVG cards in the
visual language of wasifsaeed.com, refreshed daily by a GitHub Action. The profile
speaks equally to recruiters and to people interested in what Wasif builds.

The technique (SVG cards shown through `<img>`, generated by Python, refreshed by a
scheduled Action) is the same idea as github.com/AVIVASHISHTA29; the design, code and
portrait style are original.

## Visual system ("Paper", matches wasifsaeed.com)

| Token | Value | Use |
|---|---|---|
| `PAPER` | `#F7F7F2` | card background |
| `PAPER_DEEP` | `#EDEDE6` | hatching, empty graph cells |
| `INK` | `#050505` | text, borders, hard shadows |
| `INK_SOFT` | `#444444` | secondary text |
| `MUTED` | `#777777` | labels, captions |
| `WHITE` | `#FFFFFF` | fill of outlined block letters |

- Display font: Archivo Black (SIL OFL). Labels and numbers: JetBrains Mono 400/700 (SIL OFL).
  Both subset to the characters used and embedded as base64 WOFF data URIs.
- Cards: 2px ink border, hard offset shadow (5px, 5px, no blur), paper background with a
  faint 45-degree hatching pattern, radius 14px.
- Labels in mono caps with a numeric prefix (`01 / BUILD`), as on the site.
- Contribution graph uses five ink levels on paper (empty cell = `PAPER_DEEP`).
- Full card width 880px (GitHub README column at 100%). Tiles and repo cards are
  293.33px wide shown at `width="33.333%"`.

## Animation

CSS keyframes inside each SVG (GitHub allows this in `<img>` SVGs; no JS, no external requests):
- Hero letters drop in, then the hard shadow slides out; pill dot pulses forever.
- Graph cells fade in column by column (total under 1.5s).
- Activity bars grow from the baseline; numbers fade up.
- Tile numbers pop in; tiles enter with a short stagger.
- `@media (prefers-reduced-motion: reduce)` disables all animation and shows the final state.

## Architecture

```
scripts/
  config.py           hand-edited values: headline, tile numbers, featured repos, links, username
  fetch_data.py       live data -> data/profile.json
  render_cards.py     entry point: reads config + data, writes cards/*.svg
  cards/
    common.py         tokens, font embedding, base CSS, card frame, text helpers
    hero.py
    heatmap.py
    activity.py
    tiles.py
    repos.py
  make_portrait.py    one-time: photo -> portrait.svg (engraving lines)
  subset_fonts.py     one-time: full fonts -> fonts/*.woff subsets
  requirements.txt
fonts/                subset WOFFs + OFL license files
data/profile.json     fetched data (committed, so renders work offline)
portrait.svg          generated portrait, inlined into hero.svg
cards/*.svg           generated cards, referenced by README.md
.github/workflows/update-cards.yml
README.md
```

Each card module exposes one function `render(cfg, data) -> str` returning SVG text.
`render_cards.py` only orchestrates and writes files.

### Data flow

`fetch_data.py`:
1. Contributions: GET `https://github.com/users/<user>/contributions` (public, no auth),
   parse `td.ContributionCalendar-day` cells (date, level) and their `tool-tip` counts.
   Derive total, current streak (today with 0 does not break it), longest streak,
   busiest day, monthly totals for the last 12 months.
2. Repos: GET `https://api.github.com/repos/<owner>/<name>` for each featured repo
   (stars, primary language). Uses `GITHUB_TOKEN` when present.
3. Trajectory: GET the repo's git tree (recursive) and count `content/entries/*.mdx`.

Output `data/profile.json` with `generated_at`, `contributions{days, total, streaks, busiest, months}`,
`repos{name: {stars, language}}`, `trajectory_entries`.

### Error handling

- Each source is fetched independently. If a source fails, its previous value from the
  existing `data/profile.json` is kept and a warning is printed.
- If the contributions page returns no calendar cells (markup change) and there is no
  previous data, exit non-zero so the Action fails visibly.
- The renderer never fetches; it only reads files, so it always produces cards.

## Portrait

`make_portrait.py <photo> portrait.svg`: grayscale, crop to a square around the face
(manual crop box via CLI args if needed), contrast-normalize, background removed to paper
by thresholding light values, then horizontal engraving lines: for each of ~70 rows,
a polyline whose stroke is split into segments with width proportional to local darkness,
plus a slight sine wave so it reads as engraving rather than scanlines. Output is a
`<g>` of paths in ink, sized to a 260x260 box. Generated once and committed.

## Workflow

`.github/workflows/update-cards.yml`
- Triggers: `schedule` daily at 06:23 UTC, `workflow_dispatch`, and `push` to `main`
  on `scripts/**`, `fonts/**`, `portrait.svg`.
- `permissions: contents: write`.
- Steps: checkout, setup Python 3.12, `pip install -r scripts/requirements.txt`,
  `python scripts/fetch_data.py`, `python scripts/render_cards.py`, commit
  `data/profile.json` and `cards/*.svg` with message `chore: refresh profile cards [skip ci]`
  only when they changed (`git diff --quiet` check, plain git, no third-party action).

## Testing

- `python scripts/render_cards.py` runs locally against the committed data.
- Each SVG parses as XML; each file is under 300 KB.
- Local preview page `preview.html` (gitignored) shows README.md's card block at 880px
  on GitHub's light and dark page colors; checked in the browser.
- After pushing the branch, the README is viewed on github.com on the branch to confirm
  GitHub renders the animations and fonts.

## Out of scope

- No skills/tech-stack card (dropped by choice).
- No light/dark variants of cards: paper cards are used in both GitHub themes, like the site.
- No auto-detection of "products" or "research" counts; those stay hand-set in `config.py`.
